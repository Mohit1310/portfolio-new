## Start with constraints, not polish
Most teams treat performance and design as separate tracks. The result is predictable: pretty but heavy interfaces, or fast but forgettable ones. A stronger approach is to design with performance constraints from the first wireframe.

<Callout type="info">
  In production work, design choices are technical decisions. If motion, typography, and layout are not planned with render cost in mind, performance debt appears quickly.
</Callout>

## Keep server and client boundaries intentional
In Next.js, keep data fetching in server components when possible and push interactivity into small client boundaries. This reduces shipped JavaScript and improves time-to-interactive.

## Build a repeatable system
Use a tight set of spacing, typography, and color tokens. Reusable patterns reduce CSS drift and improve maintainability.

- Limit client components to where they are required.
- Monitor Core Web Vitals continuously.
- Keep visual language consistent across sections.
